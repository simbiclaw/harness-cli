🎯 Key Decisions
TIER C Use worktree isolation for sequential dependent agents
Initial assumption was that sequential dependent tasks should use worktree isolation. However, this creates a category error — sequential tasks need shared filesystem state, not isolation. Changed to "no worktree for sequential dependent agents".
Source: Execution note M3, docs/conventions/pev-loop.md
TIER C Push write operations to structural test layer
Instead of hooks writing directly, push write operations (like checkbox flips) to be validated by structural tests first. This creates a cleaner separation between detection and action.
Source: 9005 M4 repair feedback gate implementation
TIER C File Scope rubric with collision detection
Added plan-level file scope tracking to detect when multiple milestones attempt to modify the same files, preventing merge conflicts and race conditions.
Source: 9005 M5 plan-level constraint system
TECHNICAL Use tmux for multi-window orchestration
Selected tmux over alternatives (screen, custom process manager) for reliable multi-pane terminal orchestration with scriptable interface.
Source: Experiment docs/experiments/tmux-orchestration/
TECHNICAL YAML over JSON for state files
YAML allows comments and is more human-readable for the signal directory and state schema files that humans may need to debug.
Source: docs/adr/0002-intents-path-as-ontology.md convention
⚡ Surprises & Discoveries
⚠️ Hook cannot trigger skill (discovered M3) We initially assumed hooks could trigger skills for complex workflows. However, this creates circular dependency risks and makes debugging difficult. Skills are now explicitly forbidden from being triggered by hooks.

Impact: Structural test added to enforce this constraint (test/harness/forbid-skill-from-hook.md)
ℹ️ Worktree path resolution nuance (discovered M4) Found that absolute paths in hooks cause issues when worktrees are moved. Changed all hook paths to be repo-relative, which resolved path resolution across different worktree locations.
ℹ️ Adversarial verification timing (discovered M7) Discovered that running adversarial verification immediately after implementation catches more issues than waiting. The "fresh eyes" effect is real — subagent B performs better when not influenced by A's reasoning trail.

📚 Lessons Learned
1. PEV loop must be enforced by code, not convention
We initially documented PEV as a "recommended workflow" but found it was easily skipped under time pressure. Only after adding structural test gates (test-first-gate, adversarial-verification-gate) did compliance become reliable.
⬆️ Promoted to: structural test + CI gate
2. Worktree isolation is a category error for sequential tasks
The mistake of using worktrees for sequential dependent agents taught us that "isolation" and "dependency" are fundamentally incompatible. This insight is now documented in pev-loop.md as an explicit anti-pattern.
⬆️ Promoted to: documentation + convention
3. Implementation notes are essential for knowledge transfer
The unified verdict/notes system (M2) revealed that implementation notes are not just for debugging—they're the primary mechanism for transferring context between subagent A and B, and to future sessions.
4. Checkbox flips must be gated
Adding the requirement that checkbox flips must pass structural tests caught several cases where milestones were marked complete before adversarial verification. This gate is now mandatory.
⬆️ Promoted to: structural test + hook
