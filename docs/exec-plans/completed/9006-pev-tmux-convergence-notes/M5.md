## Adversarial Edge Case Analysis

### Edge Case 1: Regex false positives (innocent text matching)
**Probe:** Test each VIOLATION_PATTERN against innocent text like "The test was skipped due to timeout", "We skipped the optional check", "rule of thumb".
**Result:** All correctly rejected. The patterns require exact phrasing: `(violated|broke|bypassed|skipped) [the] (rule|harness|convention|guard)[:\s]` plus capture. "test was skipped" does not match because `test\s+skipped` requires whitespace-only between words, not intervening content words.
**Classification:** No defect. Regex patterns are well-tuned — no false positives from innocent text.

### Edge Case 2: Slug collision divergence (underscore vs hyphen)
**Probe:** Compare `_slugify("hook bypassed pre_tool_use")` vs `_slugify("hook bypassed pre-tool-use")`.
**Result:** `_slugify` strips underscores (`[^a-z0-9\s-]` removes `_`) but keeps hyphens. Output:
- `hook bypassed pre_tool_use` → `hook-bypassed-pretooluse`
- `hook bypassed pre-tool-use` → `hook-bypassed-pre-tool-use`
**These are DIFFERENT slugs** even though they refer to the same path.
**Classification:** Semantic — low severity. Underscore-vs-hyphen inconsistency in rule descriptions could cause the same rule to be tracked under two slugs. Acceptable for now; can be fixed by converting both underscores and hyphens to the same separator.

### Edge Case 3: Same-plan self-repeats
**Probe:** Multiple occurrences of "violated the rule: commit format" in the same file.
**Result:** `_extract_violations` captures each occurrence separately. However, the repeat check uses `len({e["plan"] for e in entries}) >= 2` — deduplicating by plan NAME. So 10 occurrences in 1 plan = not flagged. Two occurrences across 2 different plans = flagged.
**Classification:** No defect. Correct behavior by design — the rule requires the same violation across DIFFERENT ExecPlans.

### Edge Case 4: Empty repo state
**Probe:** Run `_scan_plans()` against the current repo (which has no retrospective files with violation patterns).
**Result:** 0 violations found. No crash. All tests pass.
**Classification:** No defect. Tracker gracefully handles any content state.

## Implementation Review

The M5 implementation is a self-contained structural test (`test_violation_tracker.py`) that:

1. **Scans** all ExecPlan files (completed, active) and retrospectives
2. **Extracts** violation descriptions via 4 regex patterns
3. **Groups** by normalized slug
4. **Flags** rules with ≥2 different plan sources
5. **Writes** violation records to `.pev-signals/violations/<slug>.json`
6. **Suggests** promotion level based on count and source directories

Key design choices verified correct:
- `_slugify` ensures 64-char max, lowercased, kebab-case
- `_extract_violations` filters noise via `len(desc) > 10`
- `_write_violation_record` creates parent dirs automatically
- `_suggest_promotion` gives 3 levels (docs→test, test→hook, hook→CI gate)
