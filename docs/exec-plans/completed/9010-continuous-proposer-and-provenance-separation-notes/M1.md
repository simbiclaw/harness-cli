### [discovery] 2026-08-27T08:55:00Z — llama.cpp KV reuse works via n_tokens rewind

The reuse pattern is: `reset()`, `eval(transcript)` once, save `n_tokens`, then per dimension `eval(suffix)` + read `scores[n_tokens-1]` + set `n_tokens = saved` to rewind. Lowering `n_tokens` truncates the logical cursor while the physical KV for the prefix stays cached, so the next dimension's suffix attends to the reused transcript. Probed on the real model before coding: a 43-token prefix stays at 43 across dimensions while each suffix brings it to 53 and back.

### [discovery] 2026-08-27T09:05:00Z — the dependency is an optional extra, lazily imported

`llama-cpp-python` is declared under a `proposer` optional-dependencies group, not the core deps, and `LlamaLogitModel` imports it lazily inside `__init__`. So the io layer carries no hard import of a heavy compiled package, tests run without it, and a different serving stack implements the same `LogitModel` protocol without pulling llama.cpp. pyproject.toml (sensitive path) was edited under the human-resolved Q1, which authorizes the dependency.
