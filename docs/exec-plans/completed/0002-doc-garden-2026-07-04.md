## 5. Decision Log

### Decision: update last-reviewed dates on stale stubs rather than refresh content

**Rationale:** `Source: docs/conventions/i-dont-know-protocol.md § "I don't know" is not a defect` — the 25 stale `proposed` files are stubs for apps (Metis, Hermes) and pipelines (audio2tree, doc2graph) that are not in this repo. The honest action is to record that the gardener reviewed them and they remain stubs. Silently bumping dates without review would be dishonest; rewriting stubs into real specs would be scope creep. The date bump documents the review happened.

### Decision: fix PRD manifest via harness-go-sync rather than hand-editing

**Rationale:** `Source: docs/conventions/i-dont-know-protocol.md` — the manifest has 4 distinct drift conditions (filename mismatch ×2, hash mismatch ×2, orphan files ×6). Hand-editing would fix symptoms but not the root cause (the manifest was generated with an older version of harness-go and the files have evolved). Running `harness-go-sync` regenerates the manifest from current state, which is the designed remediation path per the `test_prd_spine_drift.py` test's own error messages.

## 6. Surprises & Discoveries

### The repo has 25 `verification-status: proposed` files that are all stubs for non-Argus apps

This was not obvious before the audit. The v6 rescope made the repo Argus-only, but the bootstrap-generated specs for Metis and Hermes were never marked as out-of-scope or archived. They sit in `proposed` state with no movement since May. The doc-gardener correctly flags them as stale, but the appropriate action is date-bumping (M3) rather than content refresh — they are honest stubs.

### The PRD manifest has naming drift (`to` vs `2`) that predates the v6 upgrade

The manifest was generated with `Audio-to-Tree(Bottom-up).md` and `Doc-to-Graph(Top-down).md` but the files on disk have always used `2` (e.g., `Audio2Tree`, `Doc2Graph`). This is a harness-go generation bug from the bootstrap run, not a change in the files — the files were never renamed.
