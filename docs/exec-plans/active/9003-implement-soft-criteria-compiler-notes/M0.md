# M0 reopen — Compiler input schemas (9003, round-3 decisions 2 & 6)

Notes for the 2026-08-12 reopen. The original M0 notes were archived to
`docs/retrospectives/9003-m0-notes-archived-2026-07-28.md`; this file records
only the reopen round.

### [plan-confirmed] — Patch-2 fields added as plain dict/list, not sub-models

`AuthoredNode.companion_docs` (`list[dict[str, Any]] | None`) and
`AuthoredNode.depends_on` (`list[str] | None`) added to the optional §3
section. Kept as plain containers per the contract — the tests assert dict
equality (`node.companion_docs == node_data["companion_docs"]`), which a
Pydantic sub-model would break on round-trip.

### [plan-confirmed] — Constraint tightening via Field constraints, fields stay required

`GenericEvaluatorSkill.dimensions` gained `Field(min_length=1)` and
`RubricItem.text` gained `Field(min_length=1)` — both fields remain required,
only empty values are rejected. `CalibrationManifest.epoch_id` gained
`Field(pattern=r"^\d{4}-\d{2}-\d{2}-[0-9a-f]{40}$")` (ISO date + external-tree
git SHA). None of the pre-existing fixtures violate the new constraints.

### [discovery] — S4 `checkable`/`audit_result` needed no schema change

The patch-2 test also exercises `signal.checkable` and `signal.audit_result`,
but `AuthoredNode.signals` is already `dict[str, list[dict[str, Any]]]` — the
new keys flow through as plain dict content. Enforcement of S4 (every signal
carries both keys) belongs to the M1 validator
(`check_checkable_audited`), not the schema.

### [plan-confirmed] — No `__init__.py` export change required

Tests import the module directly via

not traverse `src/argus/types/__init__.py`. The gate's Allowed Writes entry
for `__init__.py` was a hedge; no edit needed.

### [discovery] — F3 whitespace-only text: after-validator chosen over strip-in-constraint

`Field(min_length=1)` alone accepts `"   "` (len 3), so the fix is a
`model_validator(mode="after")` on `RubricItem` raising ValueError when
`text.strip() == ""`. mode="after" was chosen over "before" because the
field constraint already ran first, guaranteeing `text` is a str of length
>= 1 — the validator needs no defensive type handling. A mode="before"
validator would receive raw input (possibly non-str) and would need to
duplicate the min_length logic. Plain `""` stays rejected by min_length;
`"   "` now rejected; real text (incl. non-ASCII, e.g. Chinese) passes
since str.strip() strips only whitespace.
