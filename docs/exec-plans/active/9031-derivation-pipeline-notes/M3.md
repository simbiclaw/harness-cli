# 9031 M3 — implementation notes

## 2026-09-18 — the fact/knowledge read boundary, found by measurement

**What happened.** The reader's first draft read *everything* through
`git show <epoch>:<relpath>` — the M13 design's "one reader, one epoch". The
acceptance test then failed with `NodeNotFound: <record> not present at
ad94252`, and the follow-up measurement found why: the tree's `.gitignore`
contains

```
# CallRecord archives (per design: "Not versioned (no git history per call)")
calls/
```

**Call records are not versioned at all** — 718 records, all git-ignored, and
zero `/calls/` paths exist at the current epoch (`ad94252`, minted by
audio2tree for the PROPER_NOUNS registration).

**The corrected boundary** (now the reader's contract):

| class | source | why |
|---|---|---|
| knowledge (`_rubric/`, manifests, capsules, history shelves) | `git show <epoch>:…` | the epoch pins the yardstick (I4) |
| facts (call records) | filesystem archive, by path | a call is not a revision of the tree; the design already said so |

"One reader, one epoch" governs everything the epoch governs; the record is
simply the call. The reader keeps one entry point and both directions behind
it; the test pins the boundary itself (records must NOT appear in the epoch —
if they do, the archival design changed and the test says to re-read
`.gitignore` before relaxing).

**Consequences recorded, not acted on:**
1. **M7 input.** R1's two-tier design says reports co-locate with the call log
   and the tree carries the daily summary JSONL. If `calls/` is unversioned by
   design, the coherent reading is that `reports/` is *also* an archive
   sibling — with version-controlled traffic limited to whatever index Metis
   and sira-proxy actually need. Settle this in M7's schema work, not here.
2. **Epoch drift is real**: the working tree carries records minted after the
   current epoch. An evaluation pins knowledge at a SHA and consumes a record
   from the archive; the record's own production epoch (if any) is not the
   evaluation's pin. Whether records should carry the epoch they were produced
   under is a question for the upstream contract (M1 §2.3) — noted there.
