# M10 — Extract `score(facts, rubric)`

**Harness violation:** implemented inline by the main session rather than by a
dispatched subagent A (`docs/conventions/pev-loop.md:39`). Recorded rather than
hidden. Adversarial verification by subagent B: **in flight**, briefed cold. No
checkbox flip until a CONFIRMED verdict is recorded.

### [plan-confirmed] 2026-09-13 — A redesign, not a move, exactly as the Contract warned

Upstream's `aggregate()` is an eight-argument report builder taking
model-authored `summary` and `suggestions` with no rubric parameter
(`simbiclaw/sim@0c2cccd core/aggregator.py:17-27`). Nothing was moved.

### [deviation] 2026-09-13 — The weight reaching the arithmetic had crossed the quarantine

- **What the plan said:** Weight is stamped onto verdicts by
  `fact_checker.py:193-196` and `is_veto` by `question_generator.py:110`.
- **What the code revealed:** Confirmed at `fact_checker.py:187` and
  `question_generator.py:110`; `core/aggregator.py:52-60` then sums
  `v.score * v.weight` off those copies. So the number deciding the score is a
  copy made inside a model-calling module, and nothing re-checks it against the
  sheet.
- **Conservative choice:** `ScorableFact` carries no `weight` field at all and
  forbids extras, so a stamped value has no way in; the only source of a weight
  is a rubric lookup inside `core/`. Same for `is_veto`.
- **Revisit:** none — this is the invariant, not a workaround.

### [deviation] 2026-09-13 — An unknown criterion scored at full strength, silently

- **What the plan said:** nothing about unknown criteria.
- **What the code revealed:** `fact_checker.py:195-196` returns weight 1.0 for a
  `rubric_id` not in the sheet. A stale or typo'd reference therefore scores at
  full unweighted strength with no diagnostic.
- **Conservative choice:** `UnknownCriterion` is raised. Under I2 a finding
  that anchors to nothing real is not scored at a default.
- **Revisit:** M19 decides what the caller does with the exception.

### [discovery] 2026-09-13 — `PARTIAL`'s treatment is inherited, not decided

Upstream's `1.0 if PASS else 0.5 if NEI else 0.0` already gives `PARTIAL` zero
credit against full weight. Preserved. Called out because it is the one outcome
nobody has argued for.

### [deviation] 2026-09-13 — `RawScore` could not re-derive itself (found during M18)

- **What the plan said:** nothing about the record's shape.
- **What the code revealed:** A record carrying only a numerator and a
  denominator cannot satisfy I5 — nothing in it says which criterion
  contributed what, so M18 could not revisit one row without re-running the
  pipeline or writing the arithmetic a second time.
- **Conservative choice:** Added `Contribution`, storing outcome, credit,
  weight and veto flag per scored row, with a validator tying `credit` to
  `outcome` so a caller cannot record `outcome=FAIL, credit=1.0` — which would
  score as a pass while still tripping the veto. Factored the arithmetic into
  `tally()` so `score` and `adjust` cannot drift.
- **Revisit:** M21 hashes the contributions; M22 decides what persists.
