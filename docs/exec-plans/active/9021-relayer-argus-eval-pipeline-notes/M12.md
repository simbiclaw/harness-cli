### [deviation] 2026-09-13 — Path B is unanchorable, but not for the reason the plan gives

- **What the plan said:** "Evidence on B's document-verification path is
  model-authored prose rather than a quotation, so it is not anchorable in its
  current form."
- **What the code revealed:** The prompt asks for a quotation.
  `simbiclaw/sim@0c2cccd models/prompts.py:328` requests
  `"key_evidence": "最关键的证据原文片段"` — the most critical *verbatim source
  fragment*. Three other things make it unanchorable, and they are worse than
  the stated one: the returned string is whatever came out of `json.loads`
  (`core/fact_checker.py:98-99`) with nothing upstream checking it against a
  source, in contrast to path A where the text is `turn.text` copied verbatim
  (`:66-72`); it is attributed to `kb_context.primary_intent_path`, which is
  `matched_paths[0]` (`knowledge/intent_retriever.py:110`), while the text the
  model actually read is every primary node concatenated (`:99-103`) then
  truncated to 3000 characters (`fact_checker.py:102`), so with more than one
  primary node a *faithful* quote is filed under the wrong document; and it
  quotes a knowledge-base document while the gate verifies against the
  transcript, so there is no span to check.
- **Conservative choice:** Route path B to `ungrounded` unconditionally, before
  the anchor is inspected — a well-formed anchor on that path would be an
  anchor nothing produced. Added a structural backstop, `NOT_FROM_TRANSCRIPT`:
  evidence carrying a `doc_path` is not transcript evidence whatever
  `checking_path` claims.
- **Revisit:** If a future milestone gives documents their own span space, path
  B becomes anchorable against the document rather than the transcript. Not
  before. Had the plan's stated cause been the real one, the fix would have
  been "verify the quote against the doc" — which is impossible here.

### [plan-confirmed] 2026-09-13 — The gate partitions rather than filters

`len(grounded) + len(ungrounded) == len(findings)`, asserted at runtime before
the result is returned. A finding with one bad evidence item is ungrounded
whole: dropping the item and grounding the remainder would be silently
discarding evidence in the one module whose job is never to do that.
