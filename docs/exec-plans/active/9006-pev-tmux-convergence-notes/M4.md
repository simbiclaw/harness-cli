## Edge Case Analysis (Adversarial — resume path)

### Edge Case 1: Corrupted state.json (invalid JSON)
**Probe:** Write garbage `"this is not valid json{{{"` to state.json, then run with `--resume`.
**Result:** Exit 0. The `[ -f "$STATE_FILE" ]` check passes (file exists), so the python3 commands run. They fail silently due to `2>/dev/null`, producing empty fallback values. The resume output shows `plan=, phase=unknown, current_milestone=0`. No explicit warning about corrupted JSON.
**Classification:** Semantic — low severity. The script gracefully degrades (does not crash) but does not warn the user that state.json has invalid JSON. The empty fields are observable but not explained.

### Edge Case 2: Resume with plan_id mismatch
**Probe:** Set state.json `plan_id` to `"plan-A"`, run with `--plan "plan-B" --resume`.
**Result:** Exit 0. Warning: "state.json plan_id (plan-A) does not match --plan (plan-B)." Prompt generated for plan-B. Correct behavior — warns but allows intentional override.
**Classification:** No defect. Warning is clear and action is correct.

### Edge Case 3: Resume with all milestones confirmed
**Probe:** Set all M0-M7 to `"confirmed"` with phase `"complete"`, run with `--milestones "0,1,2" --resume`.
**Result:** Exit 0. Script produces normal prompt with checkpoint instructions. Resume state shows `phase=complete`. No crash, no infinite loop.
**Classification:** No defect. The script is agnostic to milestone status (it's the B prompt that decides).

### Edge Case 4: state.json missing required keys
**Probe:** Write minimal state `{"plan_id": "9006-pev-tmux-convergence"}` (missing `phase`, `milestones`, etc.), run with `--resume`.
**Result:** Exit 0. Missing `phase` key triggers KeyError in python3, swallowed by `||`, producing `"unknown"`. Missing `milestones` key — the script only reads `plan_id`, `phase`, `current_milestone`, so missing milestones is not checked during resume header.
**Classification:** No defect. Graceful degradation via `||` fallbacks (`"unknown"`, `"0"`, `""`).

## Implementation Review

The M4 changes add two prompt lines to `pev_subagent_adversarial.sh` (lines 190-192):

```
After each verdict, update the checkpoint at .pev-signals/state.json to
record the milestone status. This enables --resume recovery if the session
is interrupted.
```

The `--resume` path (lines 86-103) correctly:
- Checks if state.json exists
- Reads `plan_id`, `phase`, `current_milestone` with error fallbacks (`||`)
- Warns if `plan_id` in state does not match `--plan` argument
- Prints resume summary before the prompt
- Generates the prompt with `RESUME_MODE=true` flag

All `python3` operations are wrapped with `2>/dev/null || echo ""` for graceful degradation.
