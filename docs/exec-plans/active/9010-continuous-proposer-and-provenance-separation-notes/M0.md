### [deviation] 2026-08-27T08:20:00Z — Serving stack swapped MLX/Apple Silicon → llama.cpp/x86_64

- **What the plan said:** D21 pins the proposer to a local open-weight model on Apple Silicon (M3 Ultra) served via MLX; M0 measures top-k exposure and throughput on that box.
- **What the code revealed:** the environment is x86_64 Linux with no MLX and no reachable Apple hardware; MLX cannot run here at all.
- **Conservative choice:** the human directed the swap to llama.cpp; `llama-cpp-python` was dep-vetted (APPROVED, downloads unverifiable behind the proxy) and installed before any code imported it. The Provider interface (M1) keeps the specific engine behind the io boundary, so the swap does not change the plan's architecture — only which local runtime serves. Recorded as a Decision Log entry, not silently.
- **Revisit:** if a production deployment later fixes on a different engine or hardware, re-run this spike there; the throughput half must be re-measured on a production model regardless (see below).

### [deviation] 2026-08-27T08:40:00Z — Real models are proxy-blocked; a synthetic GGUF was used

- **What the plan said:** run the spike against the pinned production model.
- **What the code revealed:** the agent proxy allows only pypi.org and files.pythonhosted.org; HuggingFace and every model host return 403, so no real GGUF is reachable.
- **Conservative choice:** synthesize a seeded random-weight tiny llama-arch GGUF (`build_tiny_gguf.py`, committed beside the harness). M0's two questions are weight-independent — top-k exposure is an API property, decode rate is a model-size property — so the capability answer is fully valid and reproducible. The throughput answer is flagged `throughput_representative: false`: a real rate for this size, not for a production model.
- **Revisit:** re-measure throughput on the production model before the capacity arithmetic (Q4) is trusted. Tracked in the artifact's caveat field and in the plan's Surprises.

### [discovery] 2026-08-27T08:35:00Z — llama.cpp's high-level logprobs API is lossy; use the low-level logit vector

`create_completion(logprobs=N)` requires `logits_all=True` and then still caps below N with a distribution-dependent count (requested 20 → 12; requested 256 → 129). The low-level `Llama.scores` vector exposes the full vocabulary. D19's per-dimension expectation must be computed from the low-level vector, not the high-level API — recorded as its own Decision Log entry because it constrains M2's implementation directly.

### [discovery] 2026-08-27T08:15:00Z — The acceptance test was verified against nine synthetic artifacts before the real one existed

A test that only fails on a missing file proves nothing about the artifact it validates.
