Item-9's pass standard reads "音量能使客户听清，不会出现忽高忽低的情况". 忽高忽低 attaches to volume, so R5 is now textually grounded, not just inferred. Item-12's pass standard explicitly allows "当确实需要时，适当礼貌的打断用户，例如：非常抱歉，打断您一下", confirming the apology mitigation. New: Item-26 also penalises "多次带有情绪的抢话、压话", a third consumer of the overlap events (§5.7). The yaml that rev. 1 of this note used drops verdict-changing clauses in 13 items (2, 4, 5, 7, 9, 10, 12, 13, 19, 20, 25, 26, 27); the source diff lists them.

Issue #25 asks the soft-compiler to turn each human rubric item into graders built from metrics, labels, regex, parameters and LLM judges. Most of the plumbing already exists. What is missing is a typed intermediate representation between Signal Decomposition (B-E, soft-criteria D12) and the facets that producers deliver. The two worked items show why. Item-9 measures the wrong construct for "语音平稳". Item-12 samples windows for an event that must be counted exhaustively, and its onset-timestamp rule cannot tell an interruption from a cooperative overlap. Both problems are fixable in the operator design, before any code is written.

Read the chain as a contract, not a pipeline. Argus states what it must decide. The soft-compiler compiles each item into an operator program and splits it in two: an extract half that audio2tree runs over the call log, and a decide half that Argus runs over the extracted evidence. Measure in the producer, decide in the consumer. Each operator declares whether it is deterministic or model-judged, so the provenance rules the spec already enforces (I2, I6) apply without a new mechanism.

§3 · OPERATOR IRA closed operator vocabulary, typed the way issue #25 already types it

Issue #25 tags every step of an item with a kind: [指标] metric, [标签] label, [超参数] hyperparameter, [LLM Judge]. Promoting those tags into a small closed vocabulary lets each item compile to a DAG of operators instead of bespoke code. The executor implements each operator once, tests it once, and every item reuses it. Item-9 and Item-12 already share a window sampler and an overlap enumerator.

Kind#25 tagStageProvenanceContract
segment—extractdet.Inter-pausal units per speaker (pause ≥ θ ms). The atom every rate and level operator reads. Channel mode (stereo/mono) and attribution confidence ride each unit.
window超参数extractdet.Selects spans to measure: census (default) or sample{N, length, seed}. A sample must be seeded and recorded. Event operators may not consume a sample (§5.4).
measure指标extractdet.A scalar over a window or unit: rate, ratio, duration, count, variance, adjacent delta. Declares unit, error and a minimum-support rule (e.g. ≥ k syllables), otherwise insufficient.
event指标extractdet.An exhaustive list of typed intervals (overlap, silence, short utterance), each with onset, offset, speakers and confidence.

3.1 — The stage rule: measure in the producer, decide in the consumer

  • Why extraction belongs to audio2tree. It needs audio, alignment and the ASR stack. The contract already says the consumer never re-derives a facet, and spec D13 keeps audio code out of src/argus/.
  • Why decisions belong to Argus. Thresholds are rubric (spec D16) and are the thing calibration changes. Keeping label/combine in Argus means a κ-driven threshold change re-labels stored evidence without re-extracting, and replay never needs audio.
  • The parameter split follows from it. Window length, IPU pause, sampling seed and onset tolerance are extraction parameters: changing one requires a re-extraction and a new operator version. Bands, counts and durations ("?次", "?秒") are decision parameters, and changing one is a rubric epoch only.

§4 · ITEM-9语速适中，能配合客户的速度，语音平稳

Rubric text (rubric_com_hotline.md): 1分 — 语速适中，能配合客户的速度，音量能使客户听清，不会出现忽高忽低的情况. 0分 — ① 语速过快或过慢，使得客户表现出沟通上的不适; ② 语音突然出现明显上升或下降，使人感到不适; ③ 电话中虽未出现抢话，可是多次出现由于接话太急等原因造成的略有重叠; ④ 客户语速很慢，客服语速快，客户表达了"需要慢一点". NA — 无.

4.1 — Findings on the issue's operator design

#Issue stepFinding
a5) the variance of speech rate across sampled windows decides 语音平稳 vs 忽高忽低WRONG CONSTRUCT. In this rubric, "语音平稳" is defined by fail ② "语音突然出现明显上升或下降" and by the pass standard "音量能使客户听清，不会出现忽高忽低的情况". In the full text, 忽高忽低 is said of 音量 (volume): the rubric itself names the construct. That is voice level (intensity, pitch), not speaking rate. Variance also measures dispersion, not suddenness: a slow steady drift has high variance and no jump, while one shouted sentence in a calm call has low variance and is exactly the failure. Use an adjacent-delta operator on intensity (dB) and F0 (semitones) between consecutive agent units, normalised to the agent's level within this call.
b3) 0.8 ≤ agent rate / customer rate ≤ 1.5 means 语速适中SOUND, INCOMPLETE. Using the customer in the same window as the reference matches the entrainment literature: speakers' speaking rates are measurably closer to their partner's than to non-partners' at session level. At turn level, though, the rate correlation is weak (r ≈ 0.15, Levitan & Hirschberg 2011), so a 10 s window is too short for a stable ratio. Add (i) a minimum support of ≥ k syllables per speaker, below which the window is insufficient; (ii) an absolute band, because a ratio of 1.0 at a fast absolute rate passes the ratio test but is still too fast; (iii) a calibrated band, since 0.8/1.5 are authoring guesses.
c3) unit 字/sDEFINE IT. Use articulation rate (syllables per second excluding pauses ≥ 250 ms), not speech rate including pauses. Otherwise a slow speaker and a hesitant one look the same. Mandarin characters ≈ syllables, so 字/s works. This settles the canonical-measure gap in §9.1 §3.5.
d3) an out-of-band ratio is labelled 语速过快 / 过慢MISSING CONDITION. Fail ① fails the call only when the rate "使客户表现不适" (made the customer uncomfortable). A ratio label alone is a candidate, not a failure. F1 = rate out of band AND a customer-discomfort marker within the next k turns: asks to repeat, "什么？", "没听清", or a slow-down request.
e— (not in the issue)BOUNDARY WITH ITEM-12. Fail ③ "接话太急略有重叠" (jumping in too fast, slight overlap) uses the same overlap events as Item-12. Without a boundary one event is penalised twice. Split by where the overlap starts: overlaps at the customer's turn end (last-item / transition-space) belong to Item-9 ③; overlaps mid-turn (interjacent) belong to Item-12 (§5.1). The full text settles this: ③ applies when "电话中虽未出现抢话".
f4) customer says "你慢一点" alone fails ④MISSING CONDITION (full text). ④ reads "客户语速很慢，客服语速快，客户表达了'需要慢一点'": three conjuncts. F4 = customer rate low (absolute band) ∧ agent/customer ratio high ∧ slow-down request. A request alone, after a long agent explanation at normal speed, is not ④.
g— (not in the issue)NEW SIGNAL (full text). The pass standard requires "音量能使客户听清". Absent a fail clause (G1), compile it as a minor signal: the customer signals they can't hear (听不清 / 大点声 / 声音太小) while the channel isn't the cause (customer-side noise measured on their channel).
h4) customer says "你慢一点" (LLM Judge)KEEP, LEXICON FIRST. 慢一点 / 慢点 / 说慢点 / 没听清 / 再说一遍 is a small closed set: run a lexicon operator first, which is deterministic and counts as independent evidence. Use the judge only as a fallback for paraphrases, and it must return a span.
i1) sample N two-speaker windowsUSE CENSUS. Rates over aligned segments are arithmetic; nothing is compute-bound. Sampling adds variance and makes the label depend on the seed. Measure all qualifying windows.

§5 · ITEM-12无无故打断客户的话或抢话、压话

Rubric text (rubric_com_hotline.md): 1分 — 不出现无故打断客户谈话、抢话、压话的情况；当客户有意打断客服的表达的时候，要适当停顿或询问客户。当确实需要时，适当礼貌的打断用户，例如：非常抱歉，打断您一下. 0分 — 出现和客户抢话现象；出现压话；当企业有意打断客服的表达的时候，不予理睬. NA — 无. (A needed, polite interruption passes; an unprovoked one, 无故, does not.)

5.1 — Onset matching attributes the overlap; it does not classify it

The issue replaces "head/tail overlap" with "does the overlap start at the agent's or the customer's speech onset". That settles attribution: who started second. It is also how commercial overtalk metrics attribute incidents (VoiceBase counts agent overtalk as "the agent started talking while the caller was already talking"). It does not settle whether the overlap was an interruption. Conversation analysis classifies an overlap by where it starts relative to the overlapped speaker's turn end, and most overlaps are benign. In the Gervits & Scheutz coding of 541 overlaps, 70% were transition-space or last-item overlaps and only 15% were interjacent (mid-turn). Two quantities are needed beyond the onset:

  • Onset position, the overlapped speaker's remaining time after the onset. If it is at most about one beat (≈ 180 ms, roughly a syllable) or only the final word, the overlap is last_item/transition and goes to Item-9 ③ at most. If the overlapped speaker still has a substantial part of the turn left, it is interjacent, an Item-12 candidate.
  • Resolution, meaning who stops. If the customer stops within the overlap, the agent's interjacent cut-in succeeded: 打断/抢话. If the customer starts during agent speech and the agent keeps talking past a yield window, that is 压话, or 不予理睬 when the customer's onset is a floor claim. The pass clause "适当停顿或询问" is the complement: the agent yields within the window or asks a question.

5.2 — Mapping the issue's three overlap types

TypeIssue definitionOperational definition

5.3 — Backchannels are the dominant false positive

An agent's "嗯 / 对 / 好的" under the customer's speech is listening, not interrupting. Separating backchannels from failed interruptions is the main confusion even for a WavLM classifier trained on two-channel audio (AUC 0.949 for failed interruptions, with most errors falling into backchannel, in a 2023 meeting-interruption study). The rule must therefore exclude an overlapping unit that is short, matches the backchannel lexicon, and leaves the overlapped speaker continuing. The issue's step 7, counting the customer's sub-1/2/3-second utterances, is the right instinct for the reverse case. A short customer unit during agent speech is either a backchannel (fine) or a failed attempt to take the floor (the agent talked over them). The lexicon separates the two.

5.4 — Count every event; don't sample windows

Interruptions are sparse events. Sampling N windows either misses them or makes the count depend on the seed. The issue's own step 6 also totals counts and durations over the whole call, which contradicts step 0's sampling. The overlap_events operator enumerates every overlap in the call. The overlap ratio is Σ overlap duration / union(speech time), with silence removed from the denominator as the issue specifies and overlap time counted once, not once per speaker.

5.5 — The substrate decides what is measurable

Overlap timing on mono, diarised audio is the weakest measurement in the pipeline. Overlapped speech is the hardest part of diarisation (pyannote reports 9.3% overlapping speech across its benchmark, with hard domains well above that). Commercial overtalk metrics that attribute agent vs caller are stereo-only (VoiceBase). On stereo recordings, per-channel voice-activity detection gives exact overlap intervals: a deterministic, independent-class signal. On mono recordings, every overlap event must carry the detector's confidence, and low-confidence events become unavailable (spec v6 I9), never counted. between_turn_pauses (§9.1 §3.4) cannot carry interjacent overlaps, because the overlapped turn does not end. Item-12 needs a new overlaps[] facet from audio2tree. Whether the hotline recordings are stereo is the first fact to establish (R4).

5.6 — "The more overlaps, the more likely" needs a calibrated function

Steps 1–3 leave "?次" and "?秒" open and argue that more and longer overlaps make an interruption more likely. That is a scoring model. Make it a deterministic one: a monotone function (logistic over count, total duration and maximum duration of qualifying events) fitted on the κ seed calls (Chain B's 50, labelled blind) and frozen as a versioned decision parameter. Until it is fitted, the item's label stays provisional and the criterion stays deferred under the κ gate. The open values are calibration targets, not authoring choices.

5.7 — A third consumer: Item-26 (added 2026-10-14)

Item-26 (沟通氛围融洽) fails on "多次带有情绪的抢话、压话", the same events as Item-12, and on "严重质问、反问", the strong end of Item-10's "轻微反问句式". Partition by an emotion qualifier: Item-12 owns every 抢话/压话 event; Item-26 owns only a repeated pattern whose overlapping units also carry an emotion marker (an intensity/F0 jump from the level-jump operator, or a hostile-lexicon hit). One event then never fails two items for the same reason. This is X3 in docs/rubric/rubric-source-diff.md.

§6 · THE JUDGE OPERATORHow a model step passes the "computable" gate

The §9.1 admission gate requires "no step left to model discretion", yet Item-9 ④ and Item-12 ①④ need a judge. The two fit together once the judge's output is the thing the gate checks:

  1. Closed binary question. One question per check, answered yes | no | cannot_determine. Decomposing criteria into binary checklist questions raised agreement between LLM evaluators from α = 0.09 (Likert-style G-Eval) to 0.48 on SummEval, and improved correlation with humans by 0.10 on average (CheckEval). That is the same move as issue #25's "derive scores from binary checks".
  2. Span or nothing. A yes must return turn id + exact quote. S3 verifies the quote (I2). The item-18 example's customer_specific_evidence: str fails this and should be migrated.
  3. Provenance stays model. A judge reading is correlated (matched against a confirmed exemplar) or redundant (text judgment on the proposer's own channel). It is never independent corroboration (I6). The combine logic over it is deterministic, which is what "computable" requires.
  4. Lexicon first. Wherever a closed phrase set covers most cases (slow-down requests, cut-in apologies, floor claims), the deterministic lexicon operator runs first, and the judge runs only when it finds nothing. This keeps most evidence in the independent class.
  5. Health per operator. Track κ per judge operator, not only per criterion, so a drifting judge can be found before it demotes the whole item.

§7 · CONSEQUENCES FOR SPEC v6Two corrections, stated with where v6 went wrong

C1
The Instrument contains model operators: v6's I9 ("no model in the Instrument") is too strong. v6 took "it does not guess" as the Instrument's scope and pushed every interpretive feature into S2. But compiled items mix operator kinds by design: Item-9 ④ and Item-12 ①④ are judges inside the same measurement program as rates and overlaps. The 9011 lane split (programmatic vs model_based) already carries the distinction the invariant needs. The invariant should constrain provenance, not model presence. Proposed I9′: deterministic readings are pure functions of (call record, operator version); model readings are span-anchored, typed model, grounded by S3, and never count as independent corroboration.
C2
Extraction runs in audio2tree, not in Argus: v6's D24 placed it in the wrong tier. v6 had S1m "apply the registry to the call record" inside Argus core. The shaping chain, and §9.1's "the consumer never re-derives a facet", put extraction in the producer. Proposed D24′: S1m verifies that each reading names a known operator id/version at the pinned epoch with a valid anchor, then runs the decide half (label with the indeterminate band, then combine). D25 (cite only fired readings) and D26 (indeterminate band) carry over unchanged into the label operator.
C3
New facet requirements on audio2tree, which belong in the §9.1 revision: inter-pausal units per speaker with syllable count and articulation rate; per-unit intensity (dB) and F0 (semitones); an overlaps[] event list with onset, offset, first/second speaker, onset class, resolution and confidence; channel_mode; and judge outputs as span-anchored records.
