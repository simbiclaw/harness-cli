A soft QA rubric exists in more than one form, and rev. 4 corrects a framing error carried since rev. 2. The Specific QA Rubric is the human version: binary 0/1/NA checklist items an inspector marks, carrying company-specific values (named phrases, numeric thresholds) and failure examples. The Generic Evaluator Skill is not a human artifact — it is an AI-executed template supplying judgment structure (four dimensions, a 1–10 scale, failure signatures, a hard-threshold mechanism), not ground truth. The compiler fuses these through the align.md item→dimension map and emits computable◆ _rubric/ nodes a proposer hunts with, a gate grounds against, and a pure function weights. Alongside — not inside — the compile sits the Calibration Manifest: human-judged fragments drawn from the Error Case Library and expertise-derived Best Practices, injected on its own channel whenever drift demands, with or without a compile run. The compiler is not a runtime stage and never sees a live call; it runs offline, per criterion, and re-runs when the rules change. It is a transformation-layer skill — a peer of audio2tree and doc2graph, and like them it converts an unstructured human artifact (here, intuition-driven quality judgment) into structured, machine-gradable INTENTS content (the _rubric/ shelf). The transformation is agentic — classifying gap types, deciding what won't reduce and must go to residue, extracting values without over-fitting is judgment, not a pure pass; but what it emits is deterministic rubric that Argus later applies as a pure function. Authoring is agentic; enforcement is pure. That seam is internal to the skill and is the line rev. 4 must not blur.

◆ "Computable" in this spec means something specific — three distinct layers, not one. The word is used throughout this spec and the v5 runtime pipeline, but it names three different things that are all Turing-computable yet play different architectural roles:
1. Compute (模型) — propose findings with referents
The model reads transcript + INTENTS, performs a forward pass, and proposes findings each carrying a grounding_signals[] with claimed referents. This IS computation — a finite sequence of matrix operations producing a deterministic output for fixed weights and inputs. But the model does NOT dispose: its output is quarantined (I1).
2. Verify (门) — confirm referents exist and match
The gate checks each proposed finding: does it anchor to a real transcript span AND a real INTENTS node at the pinned git-SHA epoch, and does the cited evidence literally satisfy the required_evidence / fail_condition spec? This too IS computation — a mechanical check against external referents. A digit has no span; a finding without a referent is ungrounded (I2).
3. Dispose (门) — decide the verdict
Pass, fail, or defer-to-human. This IS computation — a pure function (score(), adjust()) of the surviving anchored findings + versioned rubric weights + case precedents — re-derivable bit-for-bit. The model's proposed score never ships (D7, D8).
The term "computable" in this spec therefore means gate-checkable — a finding is computable when it carries a referent the gate can deterministically verify against. A model output without a referent IS Turing-computable but is NOT "computable" in the spec's sense: it cannot survive the grounding pass. The pipeline's honesty is not that everything is computable; it is that the boundary between computable and uncomputable is explicitly named (gap_type, gap_rationale, residue) and reported in the manifest.
The machine rubric is not a faithful translation of the human rubric — it is a lossy projection of it. The compilable part becomes triggers; the part that won't reduce to a check ("substantive rather than scripted", "genuine not performative") stays human and routes to a person. So the output is always two things: the machine nodes and a declared residue manifest naming what was left behind — including whole criteria no dimension covers (Item 24). A compiler that emits only the nodes, and silently drops the residue, is the failure this spec exists to prevent.

§0 · TWO PIPELINESWhere the methodology lives

"Front-end" means front-end of the authoring pipeline, not a stage ahead of the evaluator. The runtime path (rev. 4) is unchanged; the authoring path runs once per criterion, before any call is evaluated.

This compiler is a transformation-layer skill, not consumer-tier code. The layer is defined by what a component produces, not the language it is written in: audio2tree emits intent structure, doc2graph emits procedural structure, and this skill emits _rubric/ nodes — all three take an unstructured human artifact and produce structured INTENTS content. So the soft-criteria compiler is a peer of audio2tree and doc2graph, homed in .claude/skills/ with its own SKILL.md, not a module buried under src/argus. What keeps this honest with the rest of the architecture is the internal seam: the skill authors rubric (agentic judgment), but the rubric it emits is applied by Argus as a pure function (deterministic enforcement). An agentic authoring skill is correct; an agentic runtime would be the C5 poison. The non-poisoning invariants therefore attach to where the skill's output goes — no rule edits from Argus output, epoch-commit-only re-entry, no src/argus write-path into INTENTS — not to the skill's own agency.
The dependency it bears. method → _rubric/ shelf → {what S2 can propose, what S3 can confirm}. Remove it and the shelf holds no judgment-layer rules; S3 has nothing to ground soft findings against; every soft finding returns deferred. That is the load — it stocks the referent — and it is borne offline. It is load-bearing with a known gap: it carries coverage, not completeness (the C3 residue stays, §6).

§0.5 · INPUT CONTRACTThree compiler inputs + one independent channel (rev. 4)

rev. 2 modeled the compiler as ingesting a single "human version." That was wrong, and it hid the real structure. The Generic Evaluator Skill is an AI-executed template, not a human artifact — it carries judgment structure, not truth. The human artifact is the Specific QA Rubric: binary items with company values. align.md bridges them. The Calibration Manifest is deliberately not a compiler input: it is an independent channel — human-judged fragments from the Error Case Library and expertise-derived Best Practices — that can be injected alone, on demand, without a compile run. Miss a compiler input and the projection is unsound; miss the manifest and the projection is sound but conservative — AUTH-9 withholds auto-final from surface-form-sensitive criteria until coverage arrives.

Output is unchanged: _rubric/ nodes + a residue manifest. The manifest now also carries dimension-coverage gaps — human criteria that map to no adequate dimension (Item 24).

The Calibration Manifest is a mechanism, not a compiler input. Per the generic skill's own calibration philosophy, its distribution is deliberately uneven — a set of countermeasures, not a curriculum. Fragments concentrate where the evaluator's cognitive bias is known to misjudge (≈2:1 danger-zone ratio: twice the anchors at misjudgment points as at excellence ceilings), because a false pass on the judgment layer costs asymmetrically more than a false flag. Its cases are drawn from the Error Case Library and expertise-derived Best Practices — the two INTENTS knowledge modules that already hold, respectively, confirmed failures and confirmed exemplars. Operationally it is embedded in the live QA loop, on its own channel:
  1. Trigger. Observed scoring deviation — falling Argus-vs-human κ or a rising escape rate on a criterion (the pipeline §6 drift detector).
  2. Injection — standalone, no compile run. Targeted human-judged cases from the Error Case Library (confirmed failures) and Best Practice Cookbook (confirmed exemplars) are annotated and committed as a new manifest epoch — aimed at the specific bias the deviation exposed, not spread evenly.
  3. Recalibration — by reference, not recompilation. Because each node's severity_map is a reference into the manifest, the injection re-anchors severity and re-evaluates AUTH-9 coverage on the existing nodes. Auto-final rights are restored (or withheld) against the new epoch. The compiler re-runs only when the rules change — manifest injections alone never require it.

Each injection is a write-time, producer-owned commit minting a new INTENTS epoch (ADR-0003) — the same non-poisoning path as every other rubric change (A7): human-judged cases enter; evaluator output never self-edits the manifest. "Supplied on demand" therefore means versioned and growing, with each epoch auditable — and separable: manifest epochs advance independently of rule epochs.

What rev. 4 adds — the gap types the compiler must handle. Sampled human-vs-generic gaps (one per inspection category) specify capabilities, not the 27 instances — so they fix the compiler's contract even before the full rubric arrives. Each maps to a concrete authoring change.
  1. Binary → continuous bridge (§2.6-A). Binary items are evidence weighed into a 1–10 dimension score, not the verdict. Triggers → grounded findings → pure score() re-derives the dimension number; the calibration manifest sets the deduction weights and the severity mapping. Two calls that both fail an item for different severities are distinguished by the manifest, not the binary.
  2. NA → applicability gate (§2.6-B, AUTH-7). An NA condition compiles into a trigger applicability_gate: condition unmet → trigger does not fire → the item is not counted as evidence for or against the dimension. NA is a structural feature of binary rubrics with no continuous counterpart; it must be compiled, not dropped.
  3. Hard-threshold synthesis (§2.6-C). "Problem Resolution < 7 = IMMEDIATE FAIL" has no single-item human equivalent. The compiler synthesizes the routing rule from a subset of binary items that collectively indicate severe failure — a many-to-one gate, not a copied threshold.
  4. Value extraction (§2.6-D, Item 4). Parse concrete values from checklist text: named phrases → lexical triggers, numeric thresholds → threshold triggers, at confidence 1.0. The gap here is specificity, not kind — the compiler extracts values, it does not merely infer forms from principles.
  5. Calibration coverage (Item 22, AUTH-9). A surface-form-sensitive judgment criterion may not auto-finalize unless the calibration manifest covers its failure surface. Without company fragments, the deflect-before-acknowledge pattern scores as helpful assistance — a systematic false positive.
  6. Escape tier by gap type (Item 16). A proxy-only criterion (a cognitive state with only lagging structural indicators) gets the most aggressive escape sampling in the rubric. escape_tier is a function of gap type, not a hand-set default: silent misdiagnosis is invisible to every structural check.
  7. Dimension-coverage gap (Item 24, AUTH-10). When a human criterion measures something no dimension covers — consequential business harm (callback inevitability, unnecessary cost, incomplete resolution) — the compiler emits lookup triggers with data_dependency declarations, defers to human until the source is connected, and flags a dimension_coverage_gap manifest row (possibly proposing a new Business Impact sub-dimension).

The v6-conformance decisions from rev. 3 (output → _rubric/, falsifiable fields, acoustic/phrase as targets, write-time re-entry) are unchanged and still hold — see §1 and §2.5.

§1 · WHAT TRANSFERSThe methodology's seven steps, adjudicated

The reference assumes the evaluator is an LLM judging prose. This pipeline moves the disposing judgment out of the model into a deterministic gate plus the §6 instrument. So each step is adjudicated against that move, not adopted wholesale.

Reference step (§04)VerdictIn this architecture
1 · Decompose into orthogonal dimensionstransfersKept, with a sharper operationalizability test: a dimension is admissible only if it reduces to a structurally checkable trigger. If it can't, it is residue (A4), not a criterion — and is declared, not forced.
2 · Replace adjectives with failure signaturestransformsThe signature is compiled into a _rubric/rules/ node carrying required_evidence + fail_condition (lexical / ordered-relation / threshold / lookup) — a falsifiable rule, not rubric prose in a skill file. An adjective trigger is rejected at authoring (AUTH-1).
3 · Weight by baseline performancereplacedThat heuristic budgets an LLM judge's attention; the gate has no attention budget. The deduction weight comes from the human rubric on the anchor; corroboration weight comes from the independence class (D2), not from baseline scores.
4 · Set hard thresholdstransformsPer-criterion minimum becomes the §6 κ-gate τ; "IMMEDIATE FAIL" critical dimensions map to compliance-layer criteria that resolve at grounding_confidence 1.0. Thresholds live on the wire, not in evaluator prose.
5 · Calibrate with few-shot examplesreplacedReplaced by the §6 agreement instrument: continuous Argus-vs-human κ on a rolling sample, versioned with the rubric, with a drift detector. The reference's one-shot, in-file calibration is the informal ancestor of this.
6 · Make criteria active, not passivetransfersStrongest transfer. An active check ("find the acknowledgment span; verify it precedes the resolution span") is the §4 applicability check — an ordered-relation trigger. Active phrasing is exactly what makes a signature compilable.
7 · Iterate the rubric itselfforbidden as writtenFree iteration against the evaluator's own output is the C5 co-degradation loop. Replaced by drift-detector-triggered re-grounding through a write-time human-confirmed commit (S6). Rules may change — only via a producer-owned commit that mints a new epoch, never by editing against Argus output (A7).
THE ONE STEP THAT MOST WANTS TO POISON THE LOOP — read before automating step 7

Step 7 in the reference is a tight loop: run evaluator → see where it diverges from you → add examples → re-run. Mechanize that with the model on both ends and you have each rubric generation trained on the last evaluator's confident errors — model collapse for verification.

The §6 instrument is what makes iteration safe: the only signal allowed to change a rule is human disagreement (falling Argus-vs-human κ), and the only path back into _rubric/ is a write-time, producer-owned commit that mints a new epoch (ADR-0003). The human is not removed from calibration; calibration is moved from synchronous (review every call) to asynchronous (sampled agreement sets the gate). It shrank and relocated — it did not vanish. An authoring tool that edits a rule directly from Argus outputs must fail review.

§2 · AUTHORING PROCEDUREFrom soft concept to wire entry

Run once per soft criterion. Output is a single _rubric/rules/ node (category = rules_criteria, layer = judgment), authored into the tree at write time. Compliance criteria do not need this procedure — they are already lexical/lookup at confidence 1.0.

A1Decompose to orthogonal dimensions

Apply the independence, exhaustiveness, and operationalizability tests. Add the residue-or-trigger test: for each dimension, can it be stated as a structural check on transcript spans / acoustic thresholds / lookups? If yes → candidate trigger. If no → it is residue; record it for A4 and stop trying to force it.

A2Compile each signature to a trigger

Translate the failure signature into a trigger with an explicit form ∈ {lexical, ordered_relation, threshold, lookup} and a spec S3 can evaluate deterministically. Example: "empathy" → "acknowledgment_span PRECEDES resolution_span within turn". No adjectives survive into the trigger.

WIRES TO Finding meta-verification in §4 of the pipeline; the trigger is what anchor_applicable checks against.
A3Classify corroborators by independence (D2)

Declare which other expertise signals back this criterion and their independence_class. Acoustic threshold entries are independent; exemplar/case matches are correlated. Declaring a soft text signal — another model-judged rules_criteria item — as a corroborator is redundant and forbidden (AUTH-4): it is the §6.4 voting prohibition in costume.

WIRES TO the §4.1 aggregator; classes are authored here, copied by S2, re-checked by S3.
A4Declare the residue — required field

Name, in residue_declared gap_rationale renamed (Patch 1 §6), what the criterion does not capture. "Acknowledge-before-resolve captures sequence; it does not capture warmth, sincerity, or sarcasm that keeps correct sequence." An entry with no declared residue is rejected (AUTH-2). This is the C3 honesty made a schema constraint, not a footnote.

A5Seed the agreement gate

Set initial tau (start 0.8) and both sampling plans for the criterion's auto-final right: a kappa_sample_plan (agreement tail — Argus-vs-human on co-reviewed calls) and an escape_sample_plan + escape_ceiling (auto-pass tail — sampled human review of what the criterion auto-passed, D11). A judgment-layer entry missing either plan is rejected (AUTH-3 / AUTH-6). This replaces the reference's few-shot calibration with a measurable, versioned, two-tailed instrument.

WIRES TO §6 of the pipeline; current_kappa starts null and is filled by the rolling sample.
A6Set deduction weight and corroboration constant

The deduction is the human rubric's weight if the criterion is violated — independent of how many instruments corroborate (corroboration moves routing, not arithmetic). The corroboration constant w_c removed from AuthoredNode (Patch 1 D6) for correlated signals is provisional (0.4); flag it for empirical measurement as 1 − corr(matcher_error, proposer_error) and log the debt in the Decision Log.

A7Register drift detection and iteration policy

Set iteration_policy to "re-ground only via S6 human confirmation; trigger edits against Argus output forbidden." The §6.3 drift detector watches this criterion's κ across windows; a fall auto-demotes it to human_review and flags for re-grounding. Iteration is human-gated, never model-gated.

§2.5 · ACOUSTIC & PHRASE ARE RUBRIC (v6)Two modules the compiler now authors, not just consumes

In rev. 2 the acoustic threshold and the phrase lexicon were treated as inputs the runtime reads — corroborating signals the compiler pointed at. Spine v6 reclassifies both from facts to rubric (ADR-0001, M3), which changes the compiler's job: the acoustic indicator framework and the phrase lexicon are now yardsticks it must author into _rubric/, alongside the rules. The measurement-vs-yardstick line is the whole point.

The split, stated once. The per-call acoustic measurement (a prosody number on the waveform) stays a runtime fact in the call record — it is what a rule's required_evidence tests against, and it remains an independent corroborator (D16). The 12-indicator framework that says which prosodic features matter and where their thresholds sit is the yardstick — versioned rubric the compiler authors into _rubric/acoustic/. Same for phrase: a matched term is a fact; the lexicon of which terms matter is rubric in _rubric/phrase/.

A2-acCompile the acoustic framework into _rubric/acoustic/ now produces EvidenceEntry; written to _rubric/evidence/acoustic/indicators.yaml (Patch 1 D2)

Author the 12 indicators as rubric nodes: each names a prosodic feature, its threshold, and the required_evidence shape a rule cites when it corroborates against the measurement. The compiler does not author the measurement (that is produced upstream per call); it authors the framework that interprets it.

WIRES TO §4.1 of the pipeline — a rule citing an acoustic measurement resolves its threshold against this framework node, never against a hardcoded constant.
A2-phCompile the phrase lexicon into _rubric/phrase/ now produces EvidenceEntry; written to _rubric/evidence/phrase/ (Patch 1 D2)

Author the lexicon as a rubric module: the terms/patterns that matter for each judgment dimension, with their match form. A rule's required_evidence of form lexical resolves against this lexicon at the pinned epoch.

WIRES TO the §4 grounding gate — Phrase/Keyword checks test the call against this lexicon (rubric), not a fact table.
Why this matters for corroboration. Because the framework and lexicon are now rubric that score() reads, they must not also be counted as independent corroborating anchors — that would double-count the rubric against itself (D16). AUTH-4's redundancy prohibition extends here: a rule may corroborate against the acoustic measurement, never against the acoustic framework it is already scored under.

§2.6 · BINARY → CONTINUOUSCompiling a human checklist into dimension evidence (rev. 4)

The Specific QA Rubric scores 27 items as 0/1/NA; the Generic Evaluator template scores four dimensions 1–10. These are incommensurable, and the compiler must bridge them without letting the binary items become the score. Binary items are evidence the pure score() weighs into a dimension number — inputs to judgment, not the judgment. Run these four steps after A1–A7, once per item, using align.md to find the item's dimension.

B-ABind the item to a dimension as weighted evidence

Via align.md, attach the item's trigger to its dimension trigger.spec removed; machine_criterion + signals replace it. Binding now attaches machine_criterion. (Patch 1 D10) with a deduction and a severity_map — a reference into the Calibration Manifest at its current epoch, mapping "which items failed and how badly" to "what 1–10 the dimension deserves." Two calls that both fail an item are separated here, by the manifest, never by the binary verdict alone. Because it is a reference, a standalone manifest injection (§0.5) re-anchors severity on existing nodes with no recompile. If no manifest exists yet, the node still compiles — but a surface-form-sensitive node cannot auto-final until coverage arrives (AUTH-9): sound, conservative, self-correcting as injections land.

WIRES TO pipeline §5 — the pure score() sums calibrated deductions into the dimension score; the binary finding is an input, never the shipped number.
B-BCompile every NA condition into an applicability gate

Translate the item's NA condition into applicability_gate.spec: a structural precondition S3 evaluates first. Gate false → the trigger does not fire and the item contributes nothing (not a pass, not a fail) to the dimension. An item with a declared NA condition and no compiled gate is rejected (AUTH-7).

WIRES TO S3 anchor_applicable — the gate runs before the finding is even proposed as evidence.
B-CSynthesize hard-fail routing from an item subset

The template's IMMEDIATE-FAIL threshold has no single-item source. Identify the subset of binary items whose collective failure indicates severe dimension failure, and author a hard_fail_rule (many-to-one) that routes the whole call to fail/human when the subset trips. This is a routing rule, not a deduction — it lives on the dimension, synthesized, not copied. stored in gates/{dimension}.yaml, never on individual nodes (Patch 1 D3)

WIRES TO pipeline §5 routing — the hard-fail rule short-circuits auto-final regardless of the weighted total.
B-DExtract concrete values from checklist text

Where the item names values — specific phrases, a numeric threshold — extract them into the trigger: values now enrich machine_criterion and signals, not a standalone trigger spec (Patch 1 D10) named phrases → lexical spec, numbers → threshold spec, at confidence 1.0 (compliance layer). The gap is specificity: do not settle for a principle-level trigger when the rubric text carries the exact value (Item 4).

WIRES TO §4 grounding — extracted values become the required_evidence spec the gate checks literally.
The coverage check every item must pass. After binding, ask: does some dimension adequately measure what this item measures? If no (Item 24 — consequential business harm has no home in the four dimensions), do not force-fit it. Emit its lookup triggers with data_dependency, set it to defer-to-human until the source is connected, and write a dimension_coverage_gap row (AUTH-10). Forcing an unmapped item into the nearest dimension is a silent-miscoding failure worse than deferring it.

3.6a — The template scaffold, decomposed (demonstration only)

Running the four generic dimensions through the compiler shows where each dimension's judgment structure lands — which parts have a structural signature at all, and where whole dimensions cross into the compliance layer. This is the skeleton the binary items will hang evidence on.

  • Procedural Accuracy was never really a judgment-layer dimension. Almost all of it is fact-lookup and ordered verification — compliance entries at confidence 1.0, no κ-gate. The template grades it 1–10 only because it grades everything uniformly. The compiler exposes that most of this "soft" dimension was objective all along.
  • Proactive Value is mostly residue. The structural part (didn't-end-abruptly) compiles; the load-bearing part ("genuinely better off") does not, and the manifest says so. Forcing it into a trigger would assert that "ended after one extra sentence" equals "left the customer better off" — the operationalization overreach §6 warns against.
  • What does NOT survive. The template's scoring machinery — grade 1–10, weighted-average ×3/×3/×2/×1 ÷ 9, honor the hard thresholds — is dropped. The signatures cross over; the "let the model grade" core does not.

§4 · PROHIBITIONSWhat the validator must refuse

  1. No adjective triggers. trigger.checkable == false trigger removed; checkable concept moves to machine_criterion (Patch 1 D10) or a spec containing an evaluative adjective ("empathetic", "polished") → reject. A trigger names a structural check, never a conclusion.
  2. No undeclared residue. A judgment-layer entry without residue_declared gap_rationale renamed (Patch 1 §6) → reject. The gap must be named where it can be audited.
  3. No ungated soft entry. A judgment-layer entry without an agreement plan → reject. Nothing soft auto-finalizes without a κ-gate.
  4. No soft⊕soft corroborator. A corroborator with independence_class: "redundant" (another model-judged text signal) → reject. Manufactured consensus is not corroboration (D5 / §6.4).
  5. No model-edited triggers. Any authoring path that mutates a trigger from Argus output rather than human confirmation → reject. Severs the C5 loop (A7).
  6. No promotion to 1.0. A layer: "judgment" entry that declares grounding_confidence 1.0 → reject. Compliance-grade certainty is for lexical/lookup criteria only; corroboration narrows the residue but never closes it (D6).
  7. No compile without a manifest. A compile run over a human rubric that has any non-fully-compilable dimension must emit a ResidueManifest row for it → reject the run if the manifest is missing. Dropping the residue silently is the one failure this spec exists to prevent.
  8. No soft entry without an escape plan. rev. 4: a judgment-layer entry whose agreement block lacks escape_sample_plan/escape_ceiling → reject. κ alone is blind to auto-passed calls; the auto-pass tail must be planned at authoring time (pipeline §6, D11).
  9. No NA condition without a compiled gate (AUTH-7). rev. 4: a source item that carries an NA condition but whose node has no applicability_gate → reject. An uncompiled NA silently turns "not applicable" into "fail" (B-B).
  10. No lookup trigger without a data-dependency declaration, and it must defer while unconnected (AUTH-8). rev. 4: a lookup trigger citing out-of-band data (callback logs, ticket status) with no data_dependency, or one whose source is connected: false that does not defer to human → reject (Item 24).
  11. No auto-final on an uncalibrated surface-form criterion (AUTH-9). rev. 4: a judgment node flagged gap_type: "calibration_surface_form" that permits auto-final while the calibration manifest does not cover its failure surface → reject. Without company fragments the criterion produces systematic false-positive passes (Item 22).
  12. No unmapped item forced into a dimension (AUTH-10). rev. 4: an item that align.md maps to no adequate dimension but which is compiled into the nearest dimension anyway, instead of emitting a dimension_coverage_gap row → reject. Silent miscoding is worse than an honest defer (Item 24).

§6 · RESIDUEWhat this companion does not solve

The methodology converts the signature-able fraction of a soft judgment and leaves the rest. Three debts are structural, not bugs to be closed:

  • The C3 residue is unbounded. residue_declared gap_rationale renamed (Patch 1 §6) makes the gap auditable; it does not measure it. There is no principled estimate of "how much of empathy this trigger captures," so no principled stopping rule — only the human queue catching what the trigger missed.
  • The escape rate measures the residue, but only its floor. rev. 4 turns "how complete is this trigger" into a tracked number (pipeline §6) — but one that counts only the misses a reviewer catches. It bounds the knowable residue from above; the unknown-unknown and the genuinely-contested call stay outside it. Report it as a floor, never as completeness.
  • wc is a measurement debt. Shipping 0.4 as a constant is the analogue of the asserted decorrelation this whole effort exists to stop asserting. It must be measured against human-labeled error correlation, or the correlated-signal weighting is itself ungrounded.
  • The authored triggers rot if the drift detector goes dark. A compiled trigger is only as good as the norm it was authored against. Without live κ and escape sampling, a criterion silently diverges and keeps auto-finalizing on a stale proxy. The companion's output depends on the instrument staying live.
The honest claim. This companion lets you shrink the human queue by converting the part of a soft judgment that has a referent, and lets you do it on terms that don't poison the loop. It does not let you retire the human inspector for the judgment layer — it makes the boundary mechanical and declares, per entry, exactly where it sits.
