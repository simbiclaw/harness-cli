## Create docs/MAP.md

Read all files under `docs/PRD/`. Write `docs/MAP.md` with this structure:

### Header

```markdown
# MAP.md — harness-go bootstrap routing aid
# Generated by harness-go Step 0. Deleted in Step 5. Do not commit to main.
```

### Routing table

One entry per downstream artifact, in chain order:

```markdown
## PRODUCT_SENSE.md + docs/product-specs/
**Read when:** <the agent decision type where reading this changes the outcome>
**Skip when:** <specific conditions under which loading this wastes context>
**Status:** pending

## DESIGN.md + docs/design-docs/
**Read when:** ...
**Skip when:** ...
**Status:** pending

## ARCHITECTURE.md + tools/lint/
**Read when:** ...
**Skip when:** ...
**Status:** pending

## QUALITY_SCORE.md
**Read when:** ...
**Skip when:** ...
**Status:** pending
```

Write routing entries in terms of **decision types**, not content summaries.
"Read when making a domain boundary decision" is correct.
"Read for architecture information" is not — it describes content, not the
decision the agent is about to make.

The "Skip when" field is load-bearing. If you cannot name a genuine skip
condition, the artifact's scope is too broad — write
`Awaiting Steering: scope unclear` rather than inventing one.
